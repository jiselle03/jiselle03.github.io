# Portfolio Roadmap

## Purpose

Position Jiselle Liu as an individual full-stack engineer for fixed-scope workflow software engagements. The site should help a prospective client understand the value of workflow discovery, product design, and delivery without relying on confidential client work as public proof.

## Publishing Policy

- Describe independent capabilities and current offers, not confidential client projects.
- Do not publish client names, project-specific domains, outcomes, timelines, screenshots, diagrams, technical architecture, code, or derived demos without the owner's written approval.
- Public demos must use an independently designed workflow, fictional data, and no client code, terminology, screens, business rules, or data.
- Treat any future client permission as asset-specific: retain the written approval alongside the exact approved wording or images.

## Phase One: Capability-Led Portfolio

- Present workflow discovery and product delivery as the core offer.
- Explain the types of systems Jiselle can build: operational portals, AI-assisted workflows, and product systems.
- Offer a direct project inquiry path for remote teams with focused operational software needs.
- Keep the site personal. Collaborators are optional capacity for a suitable engagement, not a separate studio brand.

## Distribution And Pipeline

- Target remote B2B product teams and agencies that need senior full-stack delivery for operational software.
- Maintain a lightweight pipeline with target account, contact, problem hypothesis, outreach dates, current status, and next action.
- Weekly baseline: ten researched prospect contacts, two agency contacts, and timely follow-ups.
- Publish site writing based on independently owned work, public research, or the concept demo. Do not turn confidential client work into unnamed stories.

## Verification And Deployment

- Run `npm run build` after portfolio or demo changes.
- Check the homepage and demo at desktop and mobile widths, including keyboard use and text overflow.
- Review changes against this publishing policy before deploying with `npm run deploy`.
- Deploy only when explicitly requested, not as part of each implementation change.
